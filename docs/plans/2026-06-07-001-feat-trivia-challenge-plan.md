# feat: Add Media Trivia Challenge Between Friends

A friend-vs-friend async trivia challenge. The initiating user selects a mode and a friend, 11 questions are generated — 10 timed multiple-choice from logged media (with random fills when a library runs short) plus a final fill-in-the-blank bonus question worth 3× points. Both users answer the same question set with animated transitions; results are compared and persisted. Questions are wiped post-completion; scores and metadata live on the dashboard forever.

---

## Problem Frame

Queued users already share media and see each other's queues — this feature extends that social layer into a playful, timed challenge. The core loop:

1. User A picks a mode + a friend → 10 multiple-choice questions from logged media + 1 fill-in-the-blank bonus (Q11)
2. User A answers Q1–Q10 in 10 seconds each, Q11 in 20 seconds → score stored (max 13 points), User B notified
3. User B answers the same identical 11-question set → results revealed to both, questions deleted
4. A compact trivia history card lives on each user's profile

The temporary question lifecycle is the key technical constraint: questions must be identical for both players but must not persist beyond the challenge lifecycle.

---

## Key Technical Decisions

**Question generation: Claude via Edge Function**
Claude generates contextual questions from actual media titles in users' logs. The edge function pattern already exists (`supabase/functions/bot-recommendations/`) and `ANTHROPIC_API_KEY` is stored in `.env.local` and should be added as a Supabase secret alongside the existing `TMDB_API_KEY`.

**Balanced mode: intersection-first split with random fills**
Fetch both users' `finished`/`in_progress` log entries. Prioritize shared titles, fill remaining slots from each user's unique media. When a user's pool is too small to fill their allocated slots, Claude generates questions about well-known titles of the same media type(s) — keeping the challenge playable regardless of library size. Allocation (for Q1–Q10):
- ≥4 shared titles → 4 shared + 3 initiator-only (or random fill) + 3 challenger-only (or random fill)
- 2–3 shared → all shared + equal fill from each user / random
- 0–1 shared → up to 5 from initiator, up to 5 from challenger, remaining are random fills
- "Random fill" = Claude generates a question about a well-known title of the selected media type(s) not already in either user's log

**Q11 is always fill-in-the-blank — worth 3 points — never from user logs**
The eleventh and final question is a standalone bonus round. It is always generated by Claude about a culturally well-known title that neither user has in their logs. It uses the `fill_in_blank` type with `accepted_answers[]` and `correct_display`, and is scored at 3 points (correct) or 0 (incorrect/timeout). Max possible score = 13. This applies across all three modes.

**Random mode: Open Trivia DB for Q1–Q9, Claude for Q10**
General knowledge trivia for the first 9 maps cleanly to the Open Trivia DB API (free, structured, no API key). Q10 is still Claude-generated fill-in-the-blank, consistent with other modes.

**Fuzzy matching for fill-in-the-blank (server-side)**
The `submit-trivia` edge function scores Q10 using Levenshtein distance on normalized text (lowercase, strip punctuation and common articles). Accepted if distance ≤ 2 for answers under 8 characters, ≤ 3 for longer. Multiple `accepted_answers` variants cover common alternate titles/spellings.

**10-second timer per question (client-side), 20-second timer for Q11**
Timer runs entirely client-side. On expiry, the answer is recorded as `-1` (timed out = 0 points) for MCQ or `""` for the fill-in-the-blank. Answers are submitted as an array only after all 11 questions are answered.

**Animated quiz transitions**
Each question slides in from the right; after an answer or timeout, a 1.5-second reveal state shows correct/incorrect feedback, then the next question bounces in. Implemented as CSS keyframe animations extending the existing `qFade`/`qUp` animation pattern in `index.css`.

**In-app notification via Supabase Realtime**
The unread badge on the Friends tab is entirely Realtime-driven today. The trivia challenge follows the same pattern: enable Realtime on `trivia_challenges`, challenger's client subscribes, badge and Friends-page card surface when a new row appears.

**No test runner currently in the project**
`package.json` has no vitest or jest. Test scenarios below describe what to verify; infrastructure setup is deferred.

## High-Level Technical Design

*Directional guidance for review, not implementation specification.*

### Question Schema (JSONB)

```
// Q1–Q10: multiple choice (11-item array, indices 0–9)
{
  type: "multiple_choice",
  question: "string",
  options: ["A","B","C","D"],
  correct_index: 0,          // 0–3
  media_title: "string|null",
  media_type: "movie|tv|book|album|null"
}

// Q11: fill in the blank (index 10) — worth 3 points
{
  type: "fill_in_blank",
  question: "The 1994 film directed by Robert Zemeckis about a man named ______ whose life story mirrors decades of American history",
  accepted_answers: ["forrest gump", "forest gump"],  // normalized, for fuzzy scoring
  correct_display: "Forrest Gump",                    // shown in reveal state
  points: 3,
  media_title: null,
  media_type: null
}
```

### Answer Submission Format

```
// From client → submit-trivia edge function
{
  challenge_id: uuid,
  answers: (number | string)[]  // length 11
  // positions 0–9: number (0–3 = selected option, -1 = timed out)
  // position 10: string (typed answer for fill_in_blank, "" = timed out)
}
```

### Scoring

```
Q1–Q10: 1 point each (max 10)
Q11:    3 points if fuzzy match passes, 0 otherwise
Max score: 13
```

### Quiz State Machine (client)

```
loading → [guard check] → quiz_active
  quiz_active:
    → question_display (timer: 10s for Q1–Q10, 20s for Q11)
    → on answer / timeout → answer_reveal (1.5s, timer paused)
    → if question < 10 → next question (slide animation)
    → if question === 10 → submitting
  submitting → results
```

### Animated Transitions

```css

@keyframes qSlideOutLeft  { from: translateX(0) → to: translateX(-100%) }
/* spring cubic-bezier(0.16, 1, 0.3, 1) matches existing qUp animation */
```

### U2. Edge Function `generate-trivia`

**Goal:** Accept a challenge request, build a media pool based on mode (with random fills when a user's library is too small), generate Q1–Q9 as multiple-choice and Q10 as fill-in-the-blank, then persist the challenge row.

**Dependencies:** U1

**Files:**
- `supabase/functions/generate-trivia/index.ts`

**Approach:**

Request body: `{ initiator_id, challenger_id, mode, media_types[] }`

Auth validation: verify bearer token resolves to `initiator_id` (same pattern as `bot-recommendations/index.ts`). Reject 403 if not.

**Media pool construction for Q1–Q9:**

For `my_media`:
- Fetch initiator's `user_media_log` where `status IN ('finished','in_progress')` and `media_type IN (media_types)`
- Target 10 items; if fewer than 10 exist, pad the remainder with random fill items — Claude is instructed to generate questions about well-known popular titles of the selected type(s) that are NOT in the user's log

For `balanced`:
- Fetch both users' finished/in_progress logs filtered by `media_types`
- Compute intersection by `media_id`
- Apply allocation algorithm (see Key Technical Decisions — targets 10 items for Q1–Q10)
- When either user's unique bucket is undersized, pad with random fill items (same Claude instruction)
- Result is always exactly 10 media contexts for Q1–Q10

For `random`:
- Fetch 10 questions from Open Trivia DB: `https://opentdb.com/api.php?amount=10&type=multiple&encode=url3986`
- Decode with `decodeURIComponent`; map to `multiple_choice` schema; no Claude call for Q1–Q10

**Q11 generation (all modes):**
- Always a separate Claude call regardless of mode
- Prompt: generate one fill-in-the-blank question about a culturally well-known title that is NOT in either user's media log. Include `accepted_answers[]` (normalized lowercase, strip punctuation, common alternate spellings), `correct_display` (canonical pretty-printed title), and `points: 3`
- Append this as index 10 of the `questions` array

**Claude call for Q1–Q10 (balanced/my_media):**
- System prompt: given a list of `{title, creator, type, is_random_fill}` items, generate exactly one `multiple_choice` question per item. Questions should be answerable by someone who has seen/read/listened to the work. Plausible distractors. Mix difficulty. Output as JSON array.
- Parse response; retry once on failure; if second attempt fails return 500

**Insert:**
- `trivia_challenges` row with `status = 'pending_initiator'` and the full 11-question `questions` JSONB

Response: `{ challenge_id }` on success.

**Patterns to follow:** `supabase/functions/bot-recommendations/index.ts` for serve/auth/service-role-client structure.

**Test scenarios:**
- `my_media` with ≥10 finished items produces 10 user-library questions + Q11 fill-in-blank → 11 total
- `my_media` with only 4 finished items produces 4 user-library + 6 random-fill questions + Q11 fill-in-blank
- `my_media` with 0 finished items produces 10 random-fill questions + Q11 fill-in-blank (no error)
- `balanced` with 5 shared titles produces 4 shared + expected splits with random fills as needed + Q11
- `balanced` with 0 shared titles and large libraries produces a clean 5+5 split + Q11
- `random` mode fetches 10 questions from OTDB for Q1–Q10, calls Claude only for Q11
- Q11 (index 10) is always `type: "fill_in_blank"` with `accepted_answers`, `correct_display`, and `points: 3`
- Bearer token mismatch returns 403
- OTDB call failure falls back gracefully (retry or 500 with clear message)
- Claude JSON parse failure retries once then returns 500

**Verification:** `supabase functions serve generate-trivia --env-file .env.local`; POST payloads for each mode; confirm 11-question array in inserted row with index-10 entry as fill_in_blank with `points: 3`.

### U3. Edge Function `submit-trivia`

**Goal:** Accept a user's 10 answers (9 multiple-choice indices + 1 fill-in-the-blank string), score them with fuzzy matching on Q10, persist the score, advance challenge status, and wipe questions when both players have answered.

**Dependencies:** U1, U2

**Files:**
- `supabase/functions/submit-trivia/index.ts`

**Approach:**

Request body: `{ challenge_id, answers: (number | string)[] }` — length 11, positions 0–9 are `number` (0–3 or -1 for timeout), position 10 is `string` ("" for timeout).

Auth + role resolution:
- Verify bearer token → `user_id`
- Fetch the challenge row
- `user_id === initiator_id` and `status === 'pending_initiator'` → initiator turn
- `user_id === challenger_id` and `status === 'pending_challenger'` → challenger turn
- Any other combination → 409

**Scoring Q1–Q10:** `answers[i] === questions[i].correct_index` (answer `-1` always scores 0); 1 point each

**Scoring Q11 (fuzzy match, 3 points):**
1. Normalize user input: lowercase, strip punctuation, trim, remove leading articles ("the", "a", "an")
2. Normalize each string in `accepted_answers` the same way
3. Award 3 points if: exact match OR Levenshtein distance ≤ 2 for normalized answers ≤ 8 chars, ≤ 3 for longer
4. Empty string (timed out) always scores 0

**Initiator submission:**
- UPDATE: `initiator_score = score`, `status = 'pending_challenger'`
- Do NOT return correct answers in the response
- Response: `{ ok: true, my_score: score, status: 'pending_challenger' }`

**Challenger submission:**
- UPDATE: `challenger_score = score`, `status = 'completed'`, `questions = NULL`, `completed_at = now()`
- Call `wipe_expired_trivia_questions()` as housekeeping
- Response: `{ initiator_score, challenger_score, winner: 'initiator'|'challenger'|'tie', my_score, their_score }`

**Patterns to follow:** `bot-recommendations/index.ts` for auth/service-role pattern; `json(data, status)` helper.

**Test scenarios:**
- Initiator submits 10 correct MCQ + correct Q11 → score = 13
- Initiator submits with 3 correct MCQ and Q11 timed out → score = 3
- Initiator submits 10 correct MCQ + wrong Q11 → score = 10
- Q11 fuzzy match: "forrest gump" matches accepted_answer "forrest gump" → 3 points
- Q11 fuzzy match: "forest gump" (one char off) within distance 2 → 3 points
- Q11 fuzzy match: "the godfather part 2" when answer is "the shining" → 0 points
- Q11 empty string (timed out) → 0 points
- Answers array length ≠ 11 → 400
- Submit as initiator when status = `pending_challenger` → 409
- Submit as non-participant → 403
- After challenger submits, row has `questions IS NULL` and `status = 'completed'`

**Verification:** Full round-trip with local functions serve; verify row state at each stage in Supabase table editor.

### U6. Quiz page `src/pages/TriviaChallengePage.jsx`

**Goal:** Full-page quiz at `/trivia/:challengeId` with a 10-second countdown per question (20 seconds for Q11), animated slide/bounce transitions, answer reveal feedback, and a results screen. Handles both the initiator's first-play and the challenger's response. Total 11 questions; max score 13.

**Approach:**

**Guard states (on mount):**
- `status === 'pending_initiator'` and `auth.uid() === initiator_id` → show quiz

**Quiz flow — Q1–Q9 (multiple choice):**

Per-question state: `phase: 'active' | 'reveal' | 'exit'`

- `active`: Question text visible, 4 tappable option buttons (labeled A/B/C/D), countdown progress bar (thin bar under question header, drains left-to-right over 10 seconds using CSS animation `@keyframes countdown`)
- Timer implemented with `setInterval`; fires every 100ms to update progress bar width; on reaching 0, triggers timeout
- On answer tap OR timeout → stop timer → transition to `reveal` phase (no going back)
- `reveal` (1.5 seconds):
  - If correct: tapped button pulses mint/green with a ✓ checkmark
  - If wrong: tapped button turns rose/red; correct answer button highlights mint/green

- After 1.5s reveal: `exit` phase — question slides out to the left (`qSlideOutLeft` 300ms), next question slides in from the right (`qSlideInRight` 300ms with `cubic-bezier(0.16,1,0.3,1)` for bounce feel)
- Progress indicator: "Question 3 of 11" at top (Q11 labeled "Bonus Round" in the indicator)

**Q11 — fill in the blank (Bonus Round, 3 pts):**
- Distinct entry animation or header callout: "⭐ Bonus Round — worth 3 points" banner before the question card slides in
- Input field with placeholder "Type your answer…"
- Timer: **20 seconds** — countdown bar drains over 20s

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Claude returns malformed JSON | Medium | try/catch + one retry with stricter prompt; fallback to OTDB on second failure |
| User has zero finished media in selected types | Low | Random fills handle this — no hard minimum, no error returned |
| Challenger never responds | Low | 48h expiry + `wipe_expired_trivia_questions()` |
| Race condition: simultaneous final submit | Very low | UPDATE WHERE clause includes `status = 'pending_challenger'`; only one write wins |
| OTDB HTML-encoded strings | Low | `encode=url3986` + `decodeURIComponent` |
| Q10 fuzzy match too lenient / too strict | Medium | Multiple `accepted_answers` variants + distance thresholds; tune at implementation time with test cases |

## Deferred Implementation Notes

- Claude model identifier should be confirmed at implementation time (use `claude-sonnet-4-5` or latest available via `ANTHROPIC_API_KEY`)

- The challenger results screen shows correct answers for all 10 questions — this requires the `questions` array at time of scoring.
